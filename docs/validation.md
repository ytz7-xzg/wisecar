## 软件环境与结果

验证环境为 Linux x86_64、GCC 13.3、C++11、CMake 4.4.3、OpenCV 4.6。

| 检查 | 结果 |
|---|---|
| CMake 完整构建，默认关闭 pigpio | 控制库、视觉库、两个示例和两个测试程序编译通过 |
| 核心代码严格编译 | `-Wall -Wextra -Werror -pedantic` 通过，修复后重新编译并运行 |
| CTest | `control`、`vision`，2/2 通过 |
| 控制测试 | 7 组通过：生命周期、输出失败、非法配置、PD 限幅/重置、几何、未配置引脚、后端异常 |
| 视觉测试 | 3 组通过：空帧与颜色占比、道路检测与丢线、预处理与去畸变 |
| `control_demo config/vehicle.conf` | 正常读取配置并输出计算结果，不访问 GPIO |
| `vision_debug --help` | 正常输出使用方法 |
| pigpio 后端源文件 | 使用官方头文件完成单文件编译；未链接真实 pigpio 库、未运行 GPIO |
| 补丁格式 | `git diff --check` 通过 |

在完整开发环境中可复现：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
cd build
ctest --output-on-failure
```

## 审查后修复

独立代码审查发现两处底盘异常路径问题，均先用回归测试复现，再修复并重新运行测试：

1. 某通道配置失败时，清理代码仍可能给未配置 PWM 范围的引脚写入停车值。现仅对已成功配置的通道尝试复位。
2. 后端抛出异常时可能绕过关闭逻辑。现捕获初始化、配置和写入异常，关闭底盘并返回失败。

这些测试使用模拟后端，验证调用顺序、返回值和状态；硬件断电或写入失败时，软件无法保证物理停车。
